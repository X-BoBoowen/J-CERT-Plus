# Input and timing protocol for the four-scale experiment

This protocol was fixed on 2026-11-23 before the first timed process in this round started. The experiment uses the four fixed graphs from the sixth revision, 32 ordered candidates per graph, and a budget of 15. The vertex counts are 10,000, 50,000, 100,000, and 500,000, respectively; the graph seed is 650101 plus the vertex count, and the edit weight magnitude is 1/8.

For each graph, the original fixture and 48 calibration right-hand sides produce the original opinion s0. Set d=max(1,max(abs(s0))) once, and apply the same division to every coordinate: s=s0/d. The four methods and ten repetitions for each graph share the same original and scaled vectors and the same candidate order. Save both vectors, the candidate endpoints, weights, edit types, and divisor. Each timed process regenerates the inputs and compares them against the saved arrays before timing.

All methods use the fixed additive tolerance δ=1e-9 in scaled gain units, consistently across graphs, rounds, methods, and repetitions. The positive-gain lower-bound test and interval-dominance rule of the original implementation apply. With fixed absolute δ, the equivalent tolerance in original gain units is d²δ, so the actual winners and stopping status are recorded. Query and calibration Jacobi-CG retain relative tolerance 2e-12 and absolute tolerance 0. Direct solves use the original CHOLMOD configuration. The existing rowwise residual bounds and directional interval tests remain in effect. Execution stops when the budget is exhausted or no selectable positive-gain action is certified. Numerical errors are handled separately.

The four methods are native Jacobi-CG cold solves, J-CERT+ Planner with the same backend, CHOLMOD Planner (with structural space reserved for catalog insertion edges), and LINVIEW-Delta with a registered projection table. Each scale has ten repetition blocks. Within each block, NumPy default_rng(871+rep) determines the execution order of the four methods, with rep=0…9. Each run uses a fresh single-threaded numerical process, executed sequentially on the same machine. The candidate ID trajectory, counters, and runtime of every process are fully recorded. Reports include medians, interquartile ranges, and median speedup ratios with 95% bootstrap intervals obtained by paired resampling within the same blocks.

Primary timing starts at each method's private numerical initialization and ends after the final commit, including factor construction or root filling of the registered projection table. Opinion calibration and scaling times are saved separately; calibration-inclusive time is the sum of primary timing, calibration, and scaling. Graph construction and per-process snapshot comparison are outside both timing measures. Peak RSS covers the entire timed process, including graph and input preparation. Independent numerical verification runs after timing is complete.
